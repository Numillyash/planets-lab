# PR #296 — граф потенциальных hostile overlap полей; не разрешение Host-конфликтов

Дата: 2026-10-24. Официальный [Minefields → Mine Destruction](https://help.planets.nu/minefields) утверждает: обычные normal поля могут пересекаться с web; web поля могут пересекаться друг с другом; normal поля разных владельцев с mutual Safe Passage или выше тоже могут пересекаться. В противном случае враждебное пересечение normal/normal вызывает последующее уничтожение по ID поля. Но порядок Host ID, количества потерь, последовательность полученных после предыдущих минных фаз и exact zero-area circle tangency не доказаны здесь; не интерпретировать граф как серверные фактические взрывы.

## Чистый исследовательский контракт

Новый `src/planets_lab/rules/mine_overlap_candidate_graph.py` получает complete typed list/tuple `LocatedMinefield` (field_id, owner_id, center Point, positive units, is_web exact Boolean) и exact map `mutual_safe_passage_by_normal_owner_pair[(min_owner_id,max_owner_id)] -> bool` для **каждой** пары различных владельцев обычных полей. Другие пары не принимаются, неизвестная дипломатия не становится False. Строго bounded <=128 полей и координаты <=1e6, max_radius only100/150; это предохранители тестового расчёта, **не пределы Host**. Локальная общая ведомость полей обязательна, отсутствие custom, protofields, манипуляций после snapshot и точность diplomacy утверждаются отдельно подтверждёнными флагами; они не являются Host evidence.

Все поля сортируются по field ID; каждая пара имеет immutable `MinefieldPairAssessment` с точным квадратом расстояния и суммой **целочисленных** радиусов `isqrt(units)`. При `distance² > (r1+r2)²` — DISJOINT; при точном равенстве **atomic ABSTAIN** (граница нулевой площади не приписывается Host); при positive overlap — WEB_NONDESTRUCTIVE (если хотя бы один web), SAME_OWNER_NONDESTRUCTIVE, MUTUAL_SAFE_PASSAGE_NONDESTRUCTIVE либо HOSTILE_NORMAL_OVERLAP_CANDIDATE при разных owners без взаимного Safe Passage. Никакие мины при этом не уничтожаются; `mine_units_destroyed=None`.

Все HOSTILE candidates образуют неориентированный граф. DFS разбивает его на отсортированные `MineConflictComponent` с category `ISOLATED_PAIR` для одной независимой пары или `COUPLED_MULTIFIELD` для трёх и более связанных полей. Это **потенциальные геометрические кандидаты**, не цепочка обработанных Host событий. Компонент хранит все ребра и IDs, edge partition invariant, returned snapshots immutable. `MineOverlapGraph` считает число полей, проверенных пар, candidate edges и типов компонент. Все `host_mine_units_destroyed=None`, `actual_field_roster_mutated=False`, `host_phase_order_verified=False`, `host_conflicts_resolved=False`, `host_diff_verified=False`.

`tests/test_mine_overlap_candidate_graph.py` охватывает normal hostile/disjoint/same owner/mutual Safe Passage/web vs normal/web vs web, точную касательную ABSTAIN, связанные цепочки и две независимые пары, отсутствие транзитивного вывода дипломатии, инвариант сортировки, strict bool/IDs/coords, 100/150 cap, пустые наборы, предел128 полей, immutability, противоречивый и неполный context. Всё — synthetic CI; no Host/corpus runtime. Режим `DOCUMENTED+TESTED conditional` только если exact final PR CI green, не `CORPUS_OBSERVED` / `DIFF_VERIFIED`.
