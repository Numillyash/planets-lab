# PR #292 — самостоятельный пространственный кандидат закладывания мин

Дата 2026-10-24. Официальная документация: https://help.planets.nu/minefields, https://help.planets.nu/minefields-examples, https://help.planets.nu/star-clusters. Предыдущие независимые компоненты: #290 isolated decay и #291 unallocated torpedo quote.

## Научная граница
Новый `minefield_placement_candidate.py` принимает НЕ фактический приказ, а `MineLayingQuote` из #291 и источник, явно подтверждающий полный предфазовый список полей, точные позиции, тип/владельца и координаты корабля. Для избежания ложной атрибуции нужен полный список полей *всех* владельцев и типов; выбирается ближайший центр только среди полей указанного владельца и normal/web типа, при точном равенстве расстояний — меньший ID. Внутреннее поле проверяется геометрически по целочисленному `isqrt(units)`, включительно на границе; если ближайшее поле не покрывает корабль, это кандидат NEW, даже если более далёкое поле покрывает. В противном случае EXPAND существующего candidate ID. Это алгоритмические расчёты *условного предложения*, а не evidence фактического Host решения.

Условия: immutable typed ID/owner/units/centers, ограниченный полный snapshot (до 5000 полей), координаты точные bounded integer, no custom/dense, не больше `max_radius²` единиц на существующее поле и прогноз, cap100/150 LY должен совпасть с входящей торпедной quote; поля других владельцев и типов не смешиваются; предварительная текущая фаза, accepted player orders, friendly code, serial order and collisions **не установлены**. Звёздные кластеры передаются полным явным набором дисков ядра `StarClusterCore(center, core_radius)`; проекция поля не должна касаться ядра или 10 LY исключения — иначе ABSTAIN. При новом поле и полном 500-field soft-limit отказ до возможного Host удаления/перенумерации. Overcapacity вызывает ABSTAIN, не молчаливое отбрасывание единиц. Пустой боезапас — NO_UNITS, не пустое поле.

`PlacementCandidate` всегда содержит `created_field_id=None`, `field_created_or_expanded=False`, `host_order_accepted_verified=False`, `host_causal_verified=False`. Нет модификации поля, транспорта боезапаса, управления ресурсами, расчёта взрыва при hostile overlap, разбиения единиц/ID allocation, server-controlled ordering, HostEngine integration. Условный флаг источника НЕ доказывает, что реальный Host это выполнил. Статус **DOCUMENTED mechanism + TESTED synthetic conditional** только при подтверждённом CI, не CORPUS_OBSERVED/DIFF_VERIFIED.
