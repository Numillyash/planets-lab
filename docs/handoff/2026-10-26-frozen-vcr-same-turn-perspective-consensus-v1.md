## Implementation

- Уже имевшийся `src/planets_lab/corpus/combat_vcr_runtime.py` строит replay case по `(battle_turn, vcr_id)` **внутри конкретной игры/хода**, использует полное VCR raw payload, минимальные `beams(id,damage,crewkill)`, `torpedos(id,damage,crewkill,combatrange)`, `settings.combatrng`, и fail-closed `CombatVcrInputConflict` при несовпадающих input signatures разных перспектив. Этот PR **не меняет боевой runtime** и не объявляет согласие подписью принятого Host orders.
- Новый `src/planets_lab/corpus/vcr_same_turn_consensus_readiness.py`: `FrozenSameTurnVcrConsensus`, только read-only агрегирование. Выборка идентична исходным 8550 соседним архивным парам, SHA `4432542b37c51f1bd94f27f9c061a8e27a850ecb08714ff55662928cb54ea659` проверяется **до reconstruction**; из пересекающихся пар каждый `source_member` учитывается ОДИН раз. Только после соответствия `game/player/embedded archive turn`, VCR section list, уникального положительного `vcr.id`, строгого `vcr.turn==archive_turn` и typed `left/right.objectid` записи допускаются к ephemeral grouping `(game,turn,vcr_id)`. При invalid/duplicate VCR IDs **атомарный отказ по архиву**. Ошибки сериализации JSON, включая NaN, ABSTAIN по записи. Сопоставление только для групп из **минимум двух РАЗНЫХ observer-player** в **одной игре и одном ходу**; отсечение повторов одного архивного member.
- Счётчики отдельно описывают согласие/расхождение хэшей **полного VCR payload**, **weapon catalog**, **combat RNG settings**, **full combat_vcr_runtime adapter signature**; условия **строго полного** input proof требуют существующих typed `beams`/ `torpedos` списков, явный `combatrng`, typed обеих owners. Их отсутствие не превращается в подтверждённый strict match даже при совпадении неполных хэшей. Помимо source qualified/unqualified records считаются single/multi-perspective groups, группы из двух и 3+ observers, exact conservation. Никаких group keys, game/member/player/VCR IDs, sha signatures, seeds, оружия, произвольных ключей или raw rows в JSON/log.
- Опциональное `analyze_corpus_coverage(...,vcr_same_turn_consensus_readiness=True)` и `tools/diagnostics/m2_public_corpus_economy_coverage_v1.py --vcr-same-turn-consensus`; стандартная схема M2 остаётся неизменной, новый `sample.vcr_same_turn_perspective_consensus_not_host_phase` только в opt-in. `tools/diagnostics/m2_validate_corpus_aggregate_evidence_v1.py` допускает только этот новый count-only раздел при прочих прежних guards; отдельный `tools/diagnostics/validate_vcr_same_turn_consensus_v1.py` выполняет fail-closed **точную allowlist схему и численные инварианты**, pin старые SHA/8550/68/224014, strict `python3 -I -S --self-test` на host БЕЗ packages/DB перед сканированием.
- НОВЫЙ самостоятельный эксперимент с отдельным `bash tools/run-public100-baseline68-vcr-same-turn-v1-with-evidence.sh` и внутренним `tools/run-public100-baseline68-vcr-same-turn-v1.sh`: тот же immutable public100 Docker read-only, CURRENT public68 guard, baseline68 game-ID cohort, frozen 8550 pair selection, Docker git/bash preflight, полный pytest, host isolated validator, exact two-stage sanitized report gate, автоматическое опубликование статуса/JSON/log/source SHA/exit на orphan `runtime-logs` через НЕИЗМЕНЁННЫЙ `tools/run-with-runtime-evidence.sh` **ДАЖЕ ABSTAIN**.
